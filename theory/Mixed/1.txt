DI / IoC

    What is Dependency Injection (DI)? How is DI different from Inversion of Control (IoC)?

    - 'tis a pattern by which an object/class receives its dependencies externally rather than creating them in the very
    class, thus the object doesn't instantiate them by itself. IoC is a principle by which the control over object creation
    and application flow is delegated to some external system, such as framework or container.

    Why is using new inside a class often considered a bad practice?

    - this is a bad practice, because thus we make tight coupling between a class and its concrete dependencies, and this leads
    to reduced flexibility, poor testability, violation of Dependency Inversion principle, since the class depends on a concrete
    implementation instead of abstractions.

    What DI styles do you know (constructor / method / setter injection)? Pros and cons of each?

    - there are several ways of DI implementation: constructor, method and setter injection.
        constructor: dependencies are passed through the class constructor; object is created in ready-to-use state; this way
    is good for required dependencies; it is less convenient for optional dependencies, may indicate that the class has
    too many responsibility.
        setter: dependencies are passed after an object creation; useful for optional dependencies; allows changing dependencies
    after instantiation; object may exist in an incomplete state, doesn't guarantee that dependency is present when needed;
        method: dependencies are passed directly into a specific method; it is good when dependency is needed only for one
    operation; helps to avoid unnecessary dependency in object state; if dependency is needed in many methods, it becomes
    repetitive; not suitable for core dependencies of an object.

    What is a DI container and what does it do?

    - it is a software component that implements inversion of control by managing the creation and resolution of objects
    and their dependencies. it by itself knows when and which implementation it is to create.

    What is the Service Locator pattern and why is it considered controversial?

    - it is a pattern in which class retrieves its dependencies from a central registry instead of receiving them via
    injection. it is considered to be controversial because it hides dependencies, looses testability, tight coupling.

    How does DI relate to the SOLID principle “Dependency Inversion Principle (DIP)”?

    - DI is a technique that helps implement Dependency Inversion Principle; DIP says that high-level modules should not
    depend on concrete implementations, instead, depend on abstractions; while DI provides a way to inject those
    abstractions into a class externally.

HTTP / HTTPS / REST

    What are the main parts of an HTTP request and an HTTP response?

    - HTTP request consists of request line (start line): request method (GET, POST...), url, http version.
    Headers: consists of metadata: host (example.com), authorization (bearer token), content-type (application/json)...
    Body (optional): something that client sends to server.
    HTTP response consists of status line: http version, status code, status message; headers; body (optional).

    What is the difference between HTTP and HTTPS? What does TLS provide?

    - unlike HTTP, HTTPS is a secure version, which works over TLS/SSL. TLS provides confidentiality, integrity, authentication.
    Actually, there are such ways of key exchange in TLS handshake as RSA and Diffie-Hellman. RSA is a deprecated one,
    because there is no forward secrecy. Modern TLS key exchange works in the following way: both sides (client and server)
    have private keys and public ones; they exchange their public keys with random values, and then each side uses
    Diffie-Hellman to independently derive the same shared secret. After that TLS uses a key derivation function to
    derive symmetric session keys from the shared secret together with the client and server random values. These
    session keys are used to encrypt communication.

    Which HTTP methods are idempotent and why does it matter in practice?

    - idempotent methods are put, delete, get, patch (sometimes), options, head. The repeated request will lead to the same result
    as the first one.

    What is REST (high level)? What is NOT required to call an API “REST”?

    - REST is an architectural style based on resources and has such principles as stateless communication, uniform interface,
    client-server architecture, typically json representation (but also can be XML or HTML), cacheability, layered system
    and code-on-demand (optional).

    When would you use status codes 200 / 201 / 204 / 400 / 401 / 403 / 404 / 409 / 422 / 500?

    - 200: OK, the request was successfully processed, the response is sent; 201: resource creation;
    204: No content (success, but with no body response); 400: Bad request (incorrect request); 401: Unauthorized;
    403: Forbidden (the user is authenticated, but does not have rights); 404: Not Found; 409: Conflict; 422: Unprocessable content;
    500: Server Error;

    How does HTTP caching work (ETag / If-None-Match, Cache-Control)?

    - HTTP caching works using headers like ETag and Cache-Control. Cache-Control defines how long a response can be cached
    without contacting the server. ETag is about resource versions and validation: the client sends If-None-Matched header
    to a server, and the server responds with 304 Not Modified if there is no new resource version.
