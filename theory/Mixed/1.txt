DI / IoC

    What is Dependency Injection (DI)? How is DI different from Inversion of Control (IoC)?

    - 'tis a pattern by which an object/class receives its dependencies externally rather than creating them in the very
    class, thus the object doesn't instantiate them by itself. IoC is a principle by which the control over object creation
    and application flow is delegated to some external system, such as framework or container.

    Why is using new inside a class often considered a bad practice?

    - this is a bad practice, because thus we make tight coupling between a class and its concrete dependencies, and
    this leads to reduced flexibility, poor testability, violation of Dependency Inversion principle, since the class
    depends on a concrete implementation instead of abstractions.

    What DI styles do you know (constructor / method / setter injection)? Pros and cons of each?

    - there are several ways of DI implementation: constructor, method and setter injection.
        constructor: dependencies are passed through the class constructor; object is created in ready-to-use state;
    this way is good for required dependencies; it is less convenient for optional dependencies, may indicate that
    the class has too many responsibility.
        setter: dependencies are passed after an object creation; useful for optional dependencies; allows changing
    dependencies after instantiation; object may exist in an incomplete state, doesn't guarantee that dependency
    is present when needed;
        method: dependencies are passed directly into a specific method; it is good when
    dependency is needed only for one operation; helps to avoid unnecessary dependency in object state; if
    dependency is needed in many methods, it becomes repetitive; not suitable for core dependencies of an object.

    What is a DI container and what does it do?

    - it is a software component that takes responsibility of managing the creation and resolution of objects
    and their dependencies. it by itself knows when and which implementation it is to create.

    What is the Service Locator pattern and why is it considered controversial?

    - it is a pattern in which class retrieves its dependencies by itself from a central registry instead of receiving
    them via injection. it is considered to be controversial because it hides dependencies, looses testability, tighten
    coupling.

    How does DI relate to the SOLID principle “Dependency Inversion Principle (DIP)”?

    - DI is a technique that helps implement Dependency Inversion Principle; DIP states that high-level modules should
    depend on abstraction rather than concrete implementations; while DI provides those dependencies from the outside
    into a class.

HTTP / HTTPS / REST

    What are the main parts of an HTTP request and an HTTP response?

    - HTTP request consists of request line (start line): request method (GET, POST...), url, http version.
    Headers: consist of metadata: host (example.com), authorization (bearer token), content-type (application/json)...
    Body (optional): something that client sends to server.
    HTTP response consists of status line: http version, status code, status message; headers; body (optional).

    What is the difference between HTTP and HTTPS? What does TLS provide?

    - unlike HTTP, HTTPS is a secure version, which works over TLS/SSL. TLS provides confidentiality, integrity, authentication.
    Actually, there are some ways of key exchange in TLS handshake: RSA or Diffie-Hellman. RSA is a deprecated one,
    because there is no forward secrecy. Modern TLS 1.3 key exchange works in the following way: firstly a client sends
    "hello" message to a server with its random client and ephemeral public key, the server replies with tls certificate,
    the server random and its ephemeral public key, then client verifies certificate, if it's ok, with the help of
    Diffie-Hellman they both independently derive identical shared secret using its own ephemeral private key and each
    other's public key; after that, they take shared secret, server random and clinet random and derive session keys with the
    help of key derivation function.

    Which HTTP methods are idempotent and why does it matter in practice?

    - idempotent methods are put, delete, get, patch (sometimes), options, head. The repeated request will lead to the
    same result as the first one.

    What is REST? What is NOT required to call an API “REST”?

    - REST is an architectural style based on resources and has such principles as stateless communication, uniform interface,
    client-server architecture, typically json representation (but also can be XML or HTML), cacheability, layered system
    and code-on-demand (optional).

    When would you use status codes 200 / 201 / 204 / 400 / 401 / 403 / 404 / 409 / 422 / 500?

    - 200: OK, the request was successfully processed, the response is sent; 201: resource creation; 204: No content
    (success, but with no body response); 400: Bad request (incorrect request); 401: Unauthorized; 403: Forbidden (the
    user is authenticated, but does not have rights); 404: Not Found; 409: Conflict; 422: Unprocessable content; 500:
    Server Error;

    How does HTTP caching work (ETag / If-None-Match, Cache-Control)?

    - HTTP caching works using headers like ETag and Cache-Control. Cache-Control defines how long a response can be cached
    without contacting the server. ETag is about resource versions and validation: the client sends If-None-Matched header
    to a server, and the server responds with 304 Not Modified if there is no new resource version.

TypeScript

    How is TypeScript different from JavaScript? What happens during compilation?

    - TypeScript is a statically typed superset of JavaScript that adds types and compile-time checks. It compiles
    to plain JavaScript.

    What’s the difference between any, unknown, and never?

    - any is used to receive any type of value and there will be no errors, so it disables type check. unknown is used
    when we are not sure what type we're expecting to receive, for unknown data (often you have to use type narrowing).
    never - preserves no value; often used to represent unreachable code paths and enforce exhaustiveness.

    Explain union vs intersection types, and type narrowing (type guards). Give an example.

    - a union type means that value can have one of several possible types. intersection - combines multiple types into
    one. type narrowing - it is a process by which typescript reduces a broad type to a more specific one, based on the
    checks in the code. type guard - they are typeof, in, instanceof or some custom function guard.

    interface vs type — differences and when would you choose one over the other?

    - Interfaces are mostly used to represent objects and class contracts, while types are something more general that
    can represent unions, intersections and more complex compositions. Also, interfaces are commonly used to model API
    response contracts.

    What are generics and why are they useful? Give an example.

    - generics allow to write reusable code that works with different types while preserving type safety. From my own
    example: i have an interface that models the API response, i'm expecting paginated response with some data, the values
    of pagination are always the same type, but the data can be different in different responses, so this is the very
    use-case of generics: i specify the data as generics and i can reuse this interface.

    What do readonly, Partial, Pick, and Omit do?

    - readonly makes properties immutable: they cannot be reassigned. partial - makes all properties optional
    (type PartialUser = Partial<User>). pick - creates a type by selecting specific properties from another one.
    omit vice versa - creates a type by removing some properties from another one.

SQL (Transactions, Indexes)

    What is a database transaction and why do we need it?

    - transaction it is a sequence of database operations treated as a single logical unit of work: it follows the
    all-or-nothing principle: either all operations are successfully committed, or, in case of error, all changes will
    be rolled back. Database transactions are needed to ensure data consistency.

    What does ACID stand for and what does each property mean?

    - ACID are transaction principles; A - atomicity - the very principle of all-or-nothing; C - consistency - a transaction
    moves the database from one valid state to another valid; I - isolation - transactions do not interfere each other;
    D - durability - once committed, data is permanently saved.

    Explain transaction isolation levels and anomalies (dirty reads, non-repeatable reads, phantom reads).

    - there are 4 types of isolation: READ UNCOMMITTED - the weakest isolation, in which transaction can see uncommitted
    changes of another one; READ COMMITTED - transaction can see results of another only if it was committed. (saves
    from dirty read); REPEATABLE READ - while transaction was not committed, nothing else cannot change or delete
    rows, which the first one has already read. (saves from non-repeatable read & phantom read). SERIALIZABLE - the
    strongest but the slowest type of isolation: it blocks any interactions while transaction is not committed. here
    transactions are executed in a sequence way. (protects from any anomaly)
    Default level of MySQL - Repeatable Read; Postgres - Read Committed.

    When would you use SELECT ... FOR UPDATE?

    - this command is used to lock rows during a transaction; so the purpose is to update some data safely.

    What is an index and why does it speed up reads but slow down writes?

    - an index is a data structure (usually B-Tree), that allows to find some data much faster without scanning the whole
    table. but it slows down such operations as inserts, deletions, updates, because it has to update indexes everytime.

    How do composite indexes work and why does column order matter?

    - a composite index is an index on multiple columns where data is sorted by the first column. column order matters,
    because it determines how efficiently the index can be used for filtering.

    How can you check whether a query uses an index (EXPLAIN / query plan)?

    - to check whether a query uses an index, you can use EXPLAIN or EXPLAIN ANALYZE and inspect the execution plan.
    if the plan shows an index scan or a used key - the index is being used, if it shows sequential or full table scan -
    it is not.

Laravel (MVC, Eloquent, Policies, Event Listeners)

    Explain MVC in Laravel: what are the responsibilities of Model, View, and Controller?

    - it is an architecture pattern which separates an application into three parts: data, presentation and control flow.
    In Laravel, model represents the data (Eloquent models, relationships). View - responsible for presenting data to a
    user (in Laravel - blade.php). Controllers - handles requests and delegates functions, operations, logic to some
    services, actions and returns a response.

    What is Eloquent ORM and what are relationships?

    - ORM - object-relational mapping, is an instrument that allows working with a database using objects instead of raw
    SQL. Relationships define how models are connected with each other. There are such relationships as one-to-one,
    many-to-one, many-to-many.

    What is the N+1 problem and how do you avoid it in Eloquent?

    - N+1 problem occurs when an application makes 1 query to fetch a list of records, and then N queries to fetch the
    related data for each record. The solution to this problem in Eloquent is eager loading
    ($users = User::with('posts')->get()).

    What is a Policy and how is it different from a Gate in Laravel?

    - a Policy is a class that organizes authorization logic to a model or resource; it is related to model. a Gate -
    is a closure-based authorization logic used for simple check.

    Where should request validation live in Laravel and why?

    - Request validation should live in form request classes. One of the purposes is logic separation.

    Why do we use events and listeners? Give a real-world example.

    - events and listeners are used to decouple application part by separating what happened from what should happen next.
    For example from my project, when a user played a track, the listener processed it and added a record to the clickhouse
    table to update track's streams.

    Why use queues in Laravel? What benefits do they provide?

    - Queues in Laravel allow us to run code asynchronously in the background. They used to move some heave or time-consuming
    operations out of the main request-response cycle.

Access Control (RBAC, ABAC)

    What is the difference between authentication and authorization?

    - Authentication is a process of verifying who the user is, while authorization is a process of determining what
    user is allowed to do.

    Explain RBAC: core concepts and how access checks typically work.

    - role-based access control - is an access control model where permissions are assigned to roles.

    Explain ABAC: what attributes are involved? Give an example policy.

    - attribute-based access control - is an access control model where access decisions are made based on some
    attributes rather than roles. For example: if the user_id === product_id allow access.
